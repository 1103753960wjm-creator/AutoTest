# TestHub Requirement Analysis 本地规则

## 1. 文件职责

本文文件属于目录级本地规则，仅约束 `apps/requirement_analysis/**` 范围内的需求分析、AI 生成任务、结果批次与来源回链相关改动。

## 2. 对象边界

- 任务对象负责表达生成任务本身、任务状态、发起上下文与入口关系
- 结果对象负责表达 AI 生成结果、结果处理状态、采纳或弃用动作
- 正式资产对象负责表达最终测试资产，不反向承担生成任务主战场职责

## 3. 页面职责收口

- 结果批次页：继续收口结果对象与处理状态表达
- 任务详情页：继续收口任务对象与结果入口，不再继续膨胀结果处理主战场
- 测试用例列表、详情、编辑页：只轻量承接来源关系，不伪装为强回链中心

## 4. 轮询与状态感知

- 进度轮询必须具备最小间隔、终态停止、失焦暂停或降频、同任务去重
- 同一 `taskId` 的状态感知优先复用统一 tracker 或统一轮询入口，不在多个页面和组件各自发起并行轮询

## 5. 幂等与兼容

- 采纳、弃用、回写来源标签等动作必须优先保证幂等性
- 旧数据、缺失来源数据、历史状态值必须保留兼容分支，不直接按“新模型一定完整”处理
- 自动评审记录与人工评审记录应分清消费入口，默认优先消费最新自动评审记录，不混入人工评审列表语义

## 6. 最低验证要求

- 至少核对任务进度展示、结果批次状态显示、来源回链入口三个关键链路
- 影响采纳、弃用、来源摘要、结果状态映射时，必须补充异常状态或旧数据兼容验证说明
