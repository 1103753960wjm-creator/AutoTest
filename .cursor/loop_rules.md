# TestHub 受控 Loop 规则

## 1. 文件职责

本文属于 B 层“项目规则”，用于定义 AI 在本仓库中执行 Loop 的进入条件、变更预算、失败处理、验证可信度、停止条件和审计记录要求。

Loop 指“修改 -> 验证 -> 观察结果 -> 修正 -> 再验证”的闭环执行。本文只允许受控 Loop，不允许无限自治。

## 2. Loop 进入条件

同时满足以下条件时，才允许进入受控 Loop：

- 已判断自治等级，且不是 L0 或 L4
- 已明确目标、非目标、范围边界和验收标准
- 已明确允许修改目录、禁止修改目录和最大修改文件数
- 已明确验证方式和失败停止条件
- 已读取 `docs/project-memory/error_event_log.md` 与 `docs/project-memory/error_prevention_log.md`
- L2/L3 任务已经完成用户确认闸门

高风险链路、契约变化、数据变化和安全相关任务不得默认进入 Loop。

## 3. Loop 合同

L3 受控 Loop 必须先写清 Loop 合同。合同模板见 `docs/task-templates/loop-contract-template.md`。

合同必须包含：

- 本轮目标
- 允许 AI 自主决定的事项
- 必须暂停询问的事项
- 变更预算
- 验证等级目标
- 错误记录方式
- 停止条件
- 回退与止损策略

没有 Loop 合同，不得用“继续试试”的方式反复改代码。

## 4. 变更预算

每轮 Loop 必须有明确变更预算。

默认预算：

| 自治等级 | 默认最大修改范围 |
| --- | --- |
| L1 | 最多 2 个相邻文件 |
| L2 | 最多 5 个已确认范围内文件 |
| L3 | 最多 8 个已确认范围内文件 |
| L4 | 禁止自动实现 |

预算必须额外写明：

- 允许修改目录
- 禁止修改目录
- 是否允许改接口
- 是否允许改模型
- 是否允许改测试
- 是否允许新增依赖
- 是否允许改规则文件

超出预算时必须暂停，不能边修边扩大范围。

## 5. 失败处理硬规则

验证失败后必须先做三件事：

1. 写入 `docs/project-memory/error_event_log.md`
2. 判断是否仍在原 Loop 合同范围内
3. 分析失败原因，再决定是否继续下一轮

明确禁止：

- 为了通过验证删除测试
- 为了通过验证降低断言
- 为了通过验证屏蔽错误或改成 warning
- 为了通过验证跳过校验
- 为了掩盖 SPA 状态问题而使用刷新、重启或清缓存兜底
- 在失败原因不明时扩大修改范围
- 同一失败连续 2 次后继续硬改

## 6. 验证可信度等级

交付时必须标注本轮最高验证等级。

| 等级 | 名称 | 含义 |
| --- | --- | --- |
| V0 | 未验证 | 只改了代码或文档，没有执行检查 |
| V1 | 静态验证 | `rg`、diff、编码、格式、`py_compile`、语法检查等 |
| V2 | 构建验证 | `npm run build`、`manage.py check`、单元测试等 |
| V3 | 行为验证 | 真实接口请求、页面操作、浏览器验证等 |
| V4 | 回归验证 | 主流程、异常流程、旧入口兼容、日志和副作用都已检查 |

交付说明必须包含：

- 本轮验证等级
- 已执行验证
- 未达到更高等级的原因
- 残余风险

## 7. 停止条件

出现以下任一情况，必须停止 Loop：

- 达到最大循环次数
- 同一失败连续 2 次
- 需要修改接口契约
- 需要修改数据模型或迁移
- 需要新增依赖
- 需要扩大修改范围
- 触发认证、权限、安全、生产配置、AI 主链、执行器、异步任务、WebSocket、报告链路
- 发现规则冲突
- 环境阻塞导致无法继续验证

停止后必须输出大白话说明：卡在哪里、已经验证什么、下一步需要用户确认什么。

## 8. Loop 运行日志

每次 L3 Loop 必须更新 `docs/project-memory/loop_run_log.md`。

至少记录：

- 任务名
- 自治等级
- Loop 合同位置或摘要
- 循环次数
- 每轮动作
- 每轮验证
- 失败事件
- 最终状态
- 是否触发暂停

## 9. 规则检查脚本

前端页面改动、规则改动或高风险链路改动完成后，应优先执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/rule_check.ps1
```

如果脚本失败，必须写入 `error_event_log.md`，并说明是新问题、既有问题还是脚本误报。

## 10. 核心硬原则

- Loop 是验证驱动的修正，不是无边界试错。
- Loop 可以提高效率，但不能替代用户确认边界。
- 失败是传感器，必须记录；不能被掩盖。
