# TestHub 存储与访问规则

## 1. 文件职责

本文文件属于 B 层“项目规则”，用于定义当前仓库长期有效的：

- 真源判定
- 数据访问方式
- 配置访问方式
- 文件落盘位置
- 客户端本地存储边界

## 2. 真源判定

### 2.1 业务数据真源

- 业务对象、流程状态、结果状态和统计数据的真源是后端数据库与后端接口响应
- 前端允许做轻量展示适配，但不得把浏览器缓存伪装成长期真源

### 2.2 UI 状态真源

- 页面筛选条件、分页参数、弹窗开关、临时选中项等 UI 状态真源是路由参数、Pinia store 或组件状态
- UI 状态需要跨页保留时，应沿用现有 store 或路由同步方案，不新增多套平行状态源

### 2.3 配置真源

- 后端配置真源是 `backend/settings.py`、`decouple.config` 与已有集中配置入口
- 前端配置真源是 Vite 环境变量与现有配置文件
- AI 相关配置真源优先是现有数据库配置与统一 AI 接入入口，不新增业务模块内散落配置
- 生产环境安全配置必须显式提供，`ALLOWED_HOSTS`、`CORS_ALLOWED_ORIGINS`、`SECRET_KEY` 不得依赖开发默认值

## 3. 前端访问链路

统一链路：

`View -> frontend/src/api/* -> frontend/src/utils/api.js -> Backend /api/*`

必须遵守：

- 页面和组件不得直接发送裸请求
- 鉴权头、token 刷新、401 处理统一沿用 `frontend/src/utils/api.js`
- 登录态失效后的路由跳转统一沿用 `frontend/src/utils/authNavigation.js`
- 仅将运行时必需信息保存到本地存储，如 token、用户基础信息和少量界面状态
- 真实业务数据不得长期依赖浏览器缓存代替后端真源

## 4. 后端访问链路

统一链路：

`backend/urls.py -> apps/<module>/urls.py -> views -> serializers/services/models`

必须遵守：

- 接口入口只做收参、调度、权限控制和响应组织
- 数据库存取优先通过 Django ORM
- 多步骤流程、第三方依赖调用、执行器链路和跨对象状态更新应进入服务层、执行器或工具层

## 5. 数据库存储规则

- 新增或修改模型时，应同步检查 `serializers.py`、`views.py`、相关查询、消费者和前端消费端
- 新增或改动接口应保持所在模块既有响应风格和兼容性，不强推全仓统一成另一套包裹结构
- 若必须使用原生 SQL，应有明确性能或兼容性理由，并限制在局部封装中

## 6. 文件与运行产物落盘规则

- 上传物、截图、录像、报告、Allure 结果等运行产物统一进入 `media` 路径体系
- 日志产物统一进入 `logs`
- Allure 工具、插件和配置统一留在 `allure`
- 新增运行产物时，应保证目录结构与业务结果可追溯，不新增散落临时目录

## 7. 配置访问规则

- 后端新增配置时，不在业务代码中继续扩散 `os.getenv`、地址常量和硬编码密钥
- `DEBUG`、`DISABLE_CSRF_FOR_API` 等关键布尔配置必须严格解析；生产环境禁止 `ALLOWED_HOSTS=*` 和 `DISABLE_CSRF_FOR_API=True`
- 前端环境配置统一通过 Vite 环境变量和现有配置入口管理，不在页面内散写环境判断
- AI 模型配置、提示词配置和行为配置优先走现有数据库配置或统一配置入口，不新增一套平行配置通路

## 8. 客户端状态与认证规则

- 用户 token、刷新 token 和过期时间统一沿用 `frontend/src/stores/user.js` 与 `frontend/src/utils/api.js` 管理
- 登录、刷新、退出相关变更时，必须同步检查本地存储、Pinia 状态、请求拦截器和路由跳转
- 登录、刷新、退出相关跳转统一走 `authNavigation`，除兜底工具外禁止直接操作 `window.location`
- 不允许同一业务数据同时依赖数据库与浏览器缓存，并靠猜测决定谁是真源

## 9. 明确禁止

- Vue 页面绕过 `frontend/src/api/*` 直接访问接口
- 在接口入口层散写文件路径拼接和运行产物目录逻辑
- 为了单次开发方便继续扩散硬编码地址、密钥和环境变量读取
- 默认用超大 `page_size` 或一次性全量拉取替代正常分页
