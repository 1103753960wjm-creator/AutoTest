## 1. 阶段 A 范围

阶段 A 先处理接口自动化自身对象闭环，不进入 AI 采纳、不进入 Web/App 自动化采纳、不迁移执行中心。

本阶段第一目标是把两个页面职责拆清楚：

```text
/api-testing/test-cases = 表格化接口测试用例资产列表，技术承接 ApiRequest
/api-testing/test-suites = 测试套件编排和执行页面，技术承接 TestSuite + TestSuiteRequest
/api-testing/automation = 旧入口兼容，重定向到 /api-testing/test-suites
```

阶段 A 覆盖：

1. 接口测试用例 / 测试套件页面职责拆分。
2. 接口测试用例移动到集合。
3. 调试工作区查看和修改所属集合。
4. 未分组策略收口，所有新建入口口径一致。
5. 请求历史“清空历史”按钮处理。
6. 套件级断言按钮处理。
7. 项目负责人字段契约修正。
8. 删除项目、集合、环境前补充级联风险提示。

用户已确认的实现取舍：

- 请求历史“清空历史”按钮必须真实实现，不移除。
- 套件级断言必须实现编辑弹窗并保存，不隐藏、不禁用。
- 套件级断言编辑弹窗样式参考当前系统已有编辑弹窗样式，保持标题、表单布局、底部按钮、间距、遮罩和居中表现一致。

阶段 A 不做：

- 不新增 `ApiTestCase` 数据表。
- 不改变 `ApiRequest` 作为接口测试用例技术承接的口径。
- 不做 AI 生成目标类型下拉。
- 不做 AI 结果采纳到 `ApiRequest`。
- 不做测试套件完整重构。
- 不做拖拽排序、批量移动、批量复制。
- 不使用整页刷新兜底。

## 2. 当前生效规则

- 前端请求必须走 `frontend/src/api/* -> frontend/src/utils/api.js`。
- 后端接口必须走 `backend/urls.py -> apps/<module>/urls.py -> views -> serializers/services/models`。
- `/api-testing/test-cases` 是接口测试用例资产列表页。
- `/api-testing/interfaces` 只作为隐藏兼容调试入口。
- `ApiRequest` 是接口测试用例原子资产。
- `TestSuite + TestSuiteRequest` 是测试套件编排资产。
- `InterfaceManagement.vue` 作为隐藏调试工作区时必须监听 `caseId/projectId` 变化，不能依赖销毁重建。
- 表单必须有 `@submit.prevent`，原生按钮必须显式 `type`。
- 禁止新增 `window.location.reload()`、`window.location.href` 兜底业务导航。

## 4. 测试包拆分

### TDD-A-001：页面职责拆分

验证目的：

- 证明接口测试用例页和测试套件页不是同一个页面换名字。

验证点：

- `/api-testing/test-cases` 展示表格列表，字段以 `ApiRequest` 为中心：
  - 用例名称
  - 请求方法
  - URL
  - 所属集合
  - 断言数
  - 更新时间
  - 操作
- `/api-testing/test-suites` 展示测试套件，字段以 `TestSuite + TestSuiteRequest` 为中心：
  - 套件名称
  - 所属项目
  - 套件内用例数
  - 执行状态
  - 最近执行时间
  - 套件操作
- 用例页不展示套件编排字段作为主字段。
- 套件页不承担接口测试用例资产总列表职责。

失败场景：

- `/api-testing/test-cases` 仍然是旧调试树。
- `/api-testing/test-cases` 主表格展示套件字段。
- `/api-testing/test-suites` 被改成接口测试用例资产列表。
- 两个页面都能编辑同一个对象但入口语义不一致。

### TDD-A-002：接口测试用例移动集合

验证目的：

- 证明已存在 `ApiRequest` 的 `collection` 可以通过页面真实修改，并且只允许移动到同项目集合。

验证点：

- 在接口测试用例表格页选择“移动集合”。
- 弹窗或下拉只展示同项目集合。
- 选择目标集合并确认后调用后端更新接口。
- 后端真实更新 `ApiRequest.collection`。
- 成功后刷新列表，所属集合变为目标集合。
- 再进入隐藏调试工作区，所属集合也显示为目标集合。

失败场景：

- 未选择目标集合提交。
- 目标集合不属于同项目。
- 当前用例没有集合或项目归属。
- 移动接口返回失败。
- 快速连续移动同一用例两次。
- 旧响应晚返回覆盖最新集合。

### TDD-A-003：隐藏调试工作区所属集合编辑

验证目的：

- 证明用户在调试工作区编辑接口测试用例时，可以看到和修改所属集合。

验证点：

- 从用例表格进入 `/api-testing/test-cases/workspace?caseId={id}&projectId={projectId}`。
- 基础信息区展示当前所属集合。
- 修改集合后保存。
- 保存后列表页、调试树和基础信息区一致。
- `caseId/projectId` query 变化时仍能选中最后点击的用例。

失败场景：

- 工作区只在 `mounted` 读取 query，切换用例不刷新。
- 项目切换后集合下拉仍展示旧项目集合。
- 保存失败但页面乐观展示成功。
- 编辑集合时误清空 method、url、headers、assertions 等请求字段。

### TDD-A-004：未分组策略收口

验证目的：

- 证明所有新建入口的集合策略一致，不再一处必须选集合、一处允许创建无项目归属用例。

推荐验收口径：

- P0 默认继续坚持“新建接口测试用例必须选择集合”。
- 列表页新建必须选择集合。
- 隐藏调试工作区新建也必须选择集合。
- 如果没有集合，应提示先创建集合或提供创建集合入口。

失败场景：

- 调试工作区顶部新增仍可创建未分组用例。
- 未分组用例无法加入套件、无法按项目过滤或历史归属异常。
- 页面把“未选择集合”静默写成 `null`。

### TDD-A-005：请求历史清空按钮处理

验证目的：

- 证明请求历史页不再存在“点击后只提示未实现”的假入口。

用户确认方案：

- 实现清空当前筛选范围历史。

必须验证：

- 清空前有二次确认。
- 清空范围明确，例如当前筛选结果、当前用例、当前项目。
- 后端真实删除或标记清理。
- 清空后列表刷新为空或数量减少。
- 清空成功后分页、统计数量和空态同步刷新。
- 清空失败时不改变当前列表，并展示明确失败原因。
- 清空接口必须经由 `frontend/src/api/api-testing.js` 封装。

失败场景：

- 只弹出“功能开发中”。
- 清空全量历史但确认文案没说明范围。
- 清空失败后列表仍显示成功。
- 清空接口绕过 `frontend/src/api/api-testing.js`。
- 清空过程中重复点击导致重复请求或状态错乱。
- 清空当前筛选范围，却误删其他项目或其他用例的历史。

### TDD-A-006：套件级断言按钮处理

验证目的：

- 证明测试套件页不再有“编辑断言”假入口。

用户确认方案：

- 实现 `TestSuiteRequest.assertions` 编辑弹窗并保存。

必须验证：

- 打开套件内某个接口用例的断言编辑弹窗。
- 展示当前 `TestSuiteRequest.assertions`。
- 保存后后端真实落库。
- 再次打开弹窗可以回显。
- 套件执行时使用套件级断言或明确说明当前执行仍使用用例断言。
- 弹窗标题、表单布局、底部按钮、宽度、间距、遮罩、居中效果参考当前系统已有编辑弹窗样式。
- 弹窗中新增、删除、编辑断言项时布局不跳动，长文本不溢出。
- 取消关闭不保存改动。
- 保存中按钮进入 loading，避免重复提交。
- 保存失败时弹窗不关闭，并展示明确错误提示。

失败场景：

- 点击按钮只提示“功能开发中”。
- 保存断言只改前端状态，不落库。
- 套件级断言和用例自身断言优先级不清。
- 弹窗样式裸露、未居中、遮罩缺失或按钮样式异常。
- 弹窗内容高度过长时无法滚动或底部按钮被遮挡。

### TDD-A-007：项目负责人字段契约

验证目的：

- 证明项目负责人字段不会误导用户。

可接受方案二选一：

- 前端只读展示负责人，不提供编辑输入。
- 后端明确支持负责人变更，并完成保存和回显。

失败场景：

- 页面可编辑负责人，但保存后后端忽略。
- 后端返回只读字段错误，但前端提示不清楚。
- 列表展示负责人和详情弹窗不一致。

### TDD-A-008：删除级联风险提示

验证目的：

- 证明删除项目、集合、环境前，用户能知道会影响哪些对象。

最低验证：

- 删除项目提示会影响集合、接口测试用例、测试套件、环境或执行历史中的相关对象。
- 删除集合提示会影响子集合和接口测试用例。
- 删除环境提示会影响使用该环境的套件、定时任务或执行配置。
- 删除前必须二次确认。

失败场景：

- 直接删除，没有风险提示。
- 只提示“确认删除？”但不说明影响范围。
- 删除失败时只显示后端异常原文。
- 删除成功后相关列表没有刷新。

## 5. 页面级验证清单

### 5.1 接口测试用例页

操作：

1. 打开 `/api-testing/test-cases`。
2. 查看表格字段。
3. 筛选项目、方法、关键字。
4. 新建接口测试用例。
5. 移动已有用例到另一个同项目集合。
6. 执行单用例。
7. 查看该用例请求历史。
8. 加入测试套件。
9. 进入隐藏调试工作区再返回列表。

通过标准：

- 页面是表格资产列表。
- 所有请求走 `frontend/src/api/api-testing.js`。
- 移动集合后展示一致。
- 操作成功、失败、阻断都有明确反馈。
- 不出现整页刷新。

### 5.2 测试套件页

操作：

1. 打开 `/api-testing/test-suites`。
2. 查看测试套件列表。
3. 新建或编辑测试套件。
4. 添加接口测试用例到套件。
5. 查看套件内用例。
6. 处理套件级断言入口。
7. 执行套件。

通过标准：

- 页面主语是测试套件，不是接口测试用例资产列表。
- 套件内用例关系来自 `TestSuiteRequest`。
- 不存在“功能开发中”假入口。
- 套件级断言编辑弹窗符合系统现有编辑弹窗视觉和交互样式。
- 套件执行不受用例表格页拆分影响。

### 5.3 请求历史页

操作：

1. 打开 `/api-testing/history`。
2. 按接口测试用例过滤历史。
3. 查看断言结果详情。
4. 验证清空历史按钮处理结果。

通过标准：

- 断言结果仍可展示。
- 清空入口真实可用，且清空范围、二次确认、刷新结果明确。
- 没有新增旧路径或裸请求。
