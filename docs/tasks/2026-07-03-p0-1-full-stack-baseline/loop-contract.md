# Loop Contract：P0.1 前后端与样式上线阻断项第一批

## 1. 本轮目标

- 让 P0.1 第一批已经确认的三条主线完成闭环：样式 token 最小集、前端请求入口收口、后端敏感接口权限补口。
- 让测试人员可以通过静态扫描、前端构建、后端编译和任务文档判断本轮是否达到交付底线。

## 2. 本轮不做

- 不做 P0.2 及后续任务，例如生产调试入口清理、SSE/WebSocket 统一封装、错误响应结构统一。
- 不做数据库模型、迁移、接口字段、返回结构或 AI/执行器/报告主链重构。
- 不批量格式化全仓，不回退用户或历史已有改动。

## 3. 自治等级

- 本轮自治等级：L3。
- 判断理由：用户已确认 Spec/SDD 与 TDD，可以在已冻结范围内执行“修改 -> 验证 -> 修正 -> 再验证”的受控闭环。
- 是否允许 Loop：是，最多 3 轮，且同一失败连续 2 次必须暂停。

## 4. 允许 AI 自主决定

- 文件搜索和代码阅读：允许。
- 局部实现细节：允许在已确认文件范围内按现有项目模式处理。
- 小范围兼容修正：允许，但只能修复本轮验证暴露的问题。
- 最小验证命令：允许选择 `rg`、`git diff --check`、`npm run build`、`py_compile`、`scripts/rule_check.ps1` 等已写入 TDD 的验证。

## 5. 必须暂停询问

- 需要修改接口字段、返回结构、路由契约或前端消费契约。
- 需要修改数据库模型、迁移、执行器主链、AI 主链或报告生成主链。
- 需要新增依赖、删除数据、清空数据或执行不可逆操作。
- 需要放宽认证、权限或生产安全配置。
- 同一验证失败连续 2 次，或发现规则冲突、环境阻塞。

## 6. 变更预算

- 最多修改文件数：以 Spec/SDD 已列文件为准；若需要超出该清单，必须暂停确认。
- 允许修改目录：`frontend/src/assets/css/`、`frontend/src/components/page-shells/`、`frontend/src/components/platform-shared/`、`frontend/src/api/`、已点名页面、`apps/requirement_analysis/`、`apps/app_automation/`、`backend/urls.py`、本任务文档目录、项目记忆文档。
- 禁止修改目录：数据库迁移、模型主结构、执行器主链、AI 主链、未确认业务模块。
- 是否允许改接口：否。
- 是否允许改模型：否。
- 是否允许改测试：否。
- 是否允许新增依赖：否。
- 是否允许改规则文件：否。

## 7. 验证目标

- 目标验证等级：V2，尽量接近 V3；若没有可用测试账号和真实数据，真实接口/页面行为验证必须如实标为未验证。
- 必须执行的验证：前端裸 axios 静态扫描、样式 token 静态扫描、后端权限高风险写法静态扫描、后端 `py_compile`、前端 `npm run build`、`git diff --check`、`scripts/rule_check.ps1`。
- 主流程验证：数据工厂和执行详情请求封装保持参数与响应消费不变；需求分析和 App 报告敏感入口不再匿名放行。
- 异常流程验证：未登录敏感访问应返回 401/403，无法真实发请求时在 VDD 说明原因。
- 旧入口或旧数据兼容验证：保持原 API 路径与字段不变，不改变数据库。

## 8. 失败处理

- 失败写入位置：`docs/project-memory/error_event_log.md`。
- 同一失败最多允许重试次数：2 次。
- 失败后允许修复范围：仅限本轮已确认文件和该失败直接相关的最小改动。
- 失败后必须暂停的条件：连续失败、需要扩大范围、需要改契约、环境不可用或验证证据不足以继续判断。

## 9. 回退与止损

- 可直接回退的文件：本轮新增 token/API/VDD/Loop 文档，以及已确认范围内的前后端代码改动。
- 不可直接回退的变更：无，本轮不涉及数据变更。
- 是否涉及数据变更：否。
- 是否涉及迁移：否。
- 是否需要 feature flag：否。
- 回退后如何验证：重新执行 TDD 中的静态扫描、前端构建和后端编译命令。

## 10. 停止条件

- TDD 中的最低静态/构建/编译验证完成，并在 VDD 中记录证据。
- 达到最大 3 轮循环。
- 同一失败连续 2 次。
- 需要扩大范围、修改契约、改模型、加依赖或放宽权限。
- 环境阻塞导致无法继续做真实请求或页面验证。
