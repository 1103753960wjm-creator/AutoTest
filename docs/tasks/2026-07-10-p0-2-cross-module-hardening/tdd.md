## 2. 大白话测试目标

- 这次测试要证明什么：
  - 生产环境不会把调试信息、token、密钥、请求头、内部错误细节暴露给用户。
  - 后端生产配置缺失或危险配置时能明确失败，不会带着不安全默认值启动。
  - SSE / WebSocket 有统一创建、关闭、错误和有限重连规则，离开页面后不继续挂连接。
  - 接口错误能被前端统一解析，页面不用每个接口单独猜错误字段。
- 用户最关心的结果是什么：
  - 页面不再出现“开发调试痕迹”。
  - 出错时能看到清楚原因，而不是无响应、白屏或控制台报一堆看不懂的信息。
  - 登录、生成进度、接口调试、App / UI 自动化页面不因为连接封装而回退。
- 哪些旧功能不能被破坏：
  - 登录、退出、刷新 token。
  - 需求分析生成测试用例和生成进度展示。
  - 接口自动化用例列表、隐藏调试工作区、测试套件。
  - App / UI 自动化已有页面入口。
  - 本地开发配置启动。
  - 已有成功接口响应结构。

## 7. 异常和边界用例

| 编号 | 场景 | 操作步骤 | 预期结果 | 通过标准 |
| --- | --- | --- | --- | --- |
| EX-01 | 缺少 `ALLOWED_HOSTS` | `DEBUG=False` 且不配置 hosts 运行检查 | 启动失败并提示 hosts 缺失 | 不允许隐式 `*` |
| EX-02 | 缺少 CORS origins | `DEBUG=False` 且不配置 CORS origins | 启动失败并提示 CORS 缺失 | 不默认放开全部来源 |
| EX-03 | 默认或弱 `SECRET_KEY` | 生产配置使用默认开发密钥 | 启动失败或明确阻断 | 不允许生产使用开发默认密钥 |
| EX-04 | 生产开启 `DISABLE_CSRF_FOR_API=True` | `DEBUG=False` 且开启该配置 | 启动失败 | 不允许生产禁用 API CSRF |
| EX-05 | SSE 未登录 | 无登录态访问 `stream_progress` | 返回 401 / 403，前端提示认证失败 | 不泄露进度 |
| EX-06 | SSE 页面离开 | 进入生成页后跳转到其他页面 | 连接关闭 | Network 不继续挂旧 SSE |
| EX-07 | SSE 连续失败 | 模拟网络断开或后端关闭 | 有有限重试和最终失败提示 | 不无限重连，不造成页面卡死 |
| EX-08 | 403 无权限对象 | 用户 B 访问用户 A 的对象 | 返回 403 / 404，错误结构可解析 | 不泄露对象内容 |
| EX-09 | 400 参数校验错误 | 提交缺必填字段请求 | 返回字段级错误 | 前端能展示关键字段原因 |
| EX-10 | 业务状态错误 | 对已处理对象重复操作 | 返回业务错误码和用户可读 message | 不显示假成功 |
| EX-11 | 外部服务错误 | 模拟 AI 配置连接失败或超时 | 返回脱敏错误 | 不输出完整 API Key 或请求头 |
| EX-12 | 生产调试日志残留 | 打开登录页、路由跳转、核心页面 | 控制台无用户信息、token、路由敏感状态 | 生产构建下无敏感调试输出 |
| EX-13 | 旧成功响应兼容 | 打开旧列表页和详情页 | 页面仍能消费旧成功响应 | 不因错误结构试点破坏成功页面 |

## 11. 失败判定

- 出现哪些现象算失败：
  - P0.1 / 阶段 A P0 回归未通过仍进入 P0.2 Execution。
  - 生产构建后控制台输出 token、用户敏感信息、API Key 或请求头。
  - 生产环境危险配置仍能启动。
  - 本地开发配置被生产校验误伤导致不能启动。
  - 页面离开后 SSE / WebSocket 仍持续连接。
  - 网络失败后无限重连、页面卡死或一直 loading。
  - 接口错误试点破坏已有成功响应展示。
  - 日志或响应中出现完整 API Key、token、Authorization、Cookie。
  - 为通过验证隐藏错误、降低权限或伪造成功。
- 验证连续失败几次必须暂停：
  - 同一失败连续 2 次必须暂停，先写入 `docs/project-memory/error_event_log.md`，再判断是否需要调整范围。
- 失败后允许修复的范围：
  - 只允许修复本轮确认范围内的文件。
  - 如果需要改接口契约、数据模型、迁移、AI 主链、执行器主链或报告主链，必须暂停重新确认。
- 失败后必须写入的日志：
  - 任意命令失败、构建失败、接口异常、页面红错、验证失败、环境阻塞或规则偏差都必须写入 `docs/project-memory/error_event_log.md`。
